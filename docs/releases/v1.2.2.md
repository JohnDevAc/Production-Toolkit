Production Toolkit 1.2.2 reduces unnecessary GitHub release requests and respects rate-limit deadlines across restarts.

- Rapid restarts reuse successful release checks for ten minutes. **Check for updates** can refresh sooner; repeat clicks within one minute reuse the last result.
- All five applications share a queue. Once GitHub reports a rate limit, the toolkit stops issuing API requests until the reset or Retry-After deadline, including after restarting the app.
- Cached results retain their original check time and **Cached** label. Local app versions and icons are still read on startup and each requested check.
- No timer or automatic retry has been added. After a block expires, a check occurs only on startup or when you click **Check for updates**.
- A successful toolkit check clears an earlier check error.

Run **Production-Toolkit-1.2.2-win-x64-Setup.exe** to update an installed copy, including while GitHub's API is rate-limited. Setup retains settings and shortcuts, closes the running toolkit and relaunches it after replacement. GitHub's shared public-IP allowance still applies.
