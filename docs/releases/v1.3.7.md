# Production Toolkit 1.3.7

The PC Agent card now shows **Running** or **Not running**. **Launch** is disabled while the matching agent is running in the current Windows session and becomes available again when it exits. If Windows prevents verification, **Running status unavailable** keeps Launch disabled until a later check confirms it has stopped. These local checks preserve setup readiness and do not change Agent configuration.

Environment update status follows the actual installed launcher. Downloading a newer setup and cancelling installation leaves **Needs updating** and the Update button visible. A verified setup remains reusable offline without being presented as an installed version. Current installed versions still hide the update button.

Invalid preference collections recover safely, preserving the original file and other valid preferences. The portable download and checksum consistently use **Production.Toolkit.exe**; the installed executable and ZIP entry remain **Production Toolkit.exe**.

This release supersedes the unissued 1.3.6 candidate. Its tag is retained as failed CI history; no 1.3.6 release assets were published. Test fixtures now disable inherited debug privileges only within the test process and restore them afterward, and async UI tests run on a WPF synchronization context. The application behavior is unchanged from the reviewed candidate.

Validation includes 419 regression/UI assertions, exact package filenames/checksums, and 21 isolated installer lifecycle assertions. The installer updates only Production Toolkit and preserves its settings and installation directory.
