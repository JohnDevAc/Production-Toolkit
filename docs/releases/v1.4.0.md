# Production Toolkit 1.4.0

- Simplified cards show app name, version, status and relevant actions. Release channels, component diagnostics and routine repair move under Details. Current apps have no Update button; a running PC Agent has Launch disabled. Explicit owner recovery shows Repair required with a Repair primary action and accurate package guidance.
- Added owner-aware Repair, Uninstall and Recheck. New product adapters exchange correlated durable results, preserve pending/restart state across Toolkit restart and keep incomplete outcomes distinct from success. Older installers retain their normal workflow and honest fallback.
- Local detection and Launch remain available while remote update/icon checks are slow or unavailable. Failed checks show “Updates unavailable”; technical details remain under Details and in logs. Connection timeouts no longer appear as user cancellation.
- Environment distinguishes configuration-app currency, Client/Server readiness and retained maintenance; its Agent readiness matches the Agent card.
- Agent Complete setup opens its native adapter wizard and rechecks actual configuration, while explicit Repair retains package-only maintenance. Partial Environment completion uses ordinary install to retain healthy components.
- Environment Open setup uses its advertised install protocol while leaving role selection and consent to the native wizard. The original request persists for reboot recovery; older setups keep honest legacy tracking. Explicit Repair retains its separate semantics.
- Lifecycle polling permits atomic result replacement without blocking the writer, retaining strict snapshot limits and validation.
- Active installers show Setup in progress or Waiting for input with one installer-window instruction. Recovery/Recheck guidance remains for unresolved operations; active status verifies the producer identity and never treats a result before process exit as completion.
- Agent partial removal no longer crashes runtime polling. Missing executables remain distinct from running status, and concurrent discovery cannot restore stale runtime state over recovery controls.
- Repair checks owner recovery state first. When a complete package is required, it uses the verified compatible selected package, preserves data and rejects downgrades or unverified versions. Ordinary healthy repair continues using retained maintenance offline.
- TestCard has a durable installation inventory independent of UI preferences, file-damage detection, cached repair, retained previous copies and safe removal/retry that preserves settings and shared dependencies.

The accepted lifecycle implementation passed 991 regression/UI assertions, isolated installer checks and coordinated Windows VM installation/repair acceptance. Release-channel selection and installer metadata have additional focused checks. Arena GPU/runtime validation and unrun Windows fault scenarios are not claimed. Each managed product retains its own repository, installer and release channel.

- Toolkit self-update follows the installed build channel: stable stays stable, development follows development prereleases. The installer must match both the semantic release version and its numeric Windows file version; no automatic channel switch is offered.
